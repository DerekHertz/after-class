# What a lecture-hour costs on current master, and the first cut

Measurement report, 2026-11-15, for issue #212. Derek's goal is a hosted beta for friends with a $5 cap per user and $50 in total. He approved this work as: "Measure the cost per lecture-hour again on the current code, and cut it until a lecture fits under the cap."

## How to read the numbers

- **Measured** means counted in a run's database. Token counts come from `claude -p` on Derek's subscription and from Jev's responses.
- **Estimated** means measured tokens priced at list prices, as the hosted Messages API adapter would be billed.
- **Projected** means an estimate for a run that was not made, from a paired measurement.
- Prices: Opus 5.5 $4 in and $20 out, Sonnet 5.5 $2 and $10, cache reads 0.05 times input, 5 minute cache writes 1.25 times (`src/backend/providers/claude-api.ts`). Jev $0.042 per million input tokens (#216).
- `claude -p` adds its own overhead to every call. A one-word call with the product's flags used 2,090 input tokens on Opus and 2,089 on Sonnet, so each Claude call is priced with 2,080 tokens taken off its input.
- Revisions are priced with the evidence cache that the hosted adapter has had since #215: the first revision of a chunk writes the evidence, later ones read it.
- Tutor turns are priced as the hosted adapter caches them: the first turn writes the system block, later turns read it.
- A lecture-hour is one hour of watched lecture.

## The short version

1. **Current master costs $3.9 to $4.0 per lecture-hour to prepare** (estimated, two lectures). A review of about five learner turns adds $0.16 to $0.19. One lecture-hour and one review is $4.0 to $4.2, which fits under $5 with little room.
2. **Evidence IDs were a third of what the interpretation wrote.** Each `ev_` ID is about 25 tokens, and an interpretation writes about 150 of them. Citing evidence by short labels such as `p12` cuts interpretation output tokens by 37 to 39% (measured on 6 paired chunks) and its estimated cost by 31 to 33% and makes it about twice as fast.
3. **With labels, one lecture-hour and one review is about $3.2** (estimated from measured tokens on the slide lecture, $3.00 to prepare plus $0.18 for the review). That is 64% of the cap. The board lecture projects to about $3.0.
4. **Revisions are now the second line, and they vary a lot.** One revision in 17.8 minutes on the board lecture, five in 20 minutes on the slide lecture. Each one resends the whole chunk's evidence.
5. **What is left is Derek's call.** Sonnet for interpretation and revision (experiment 4 did not pass its bar), lower effort, and smaller or fewer frames would each cut more. None of them is shipped here.

## What the budget counts

- **Locally**, the budget counts what `claude -p` reports, which is notional subscription cost with 1-hour cache writes and the CLI's overhead. Run A counted $1.96, run B $2.48 and run C $1.96 against a $100 cap set for the test (measured). That is 1.5 to 1.7 times the estimates above.
- **Hosted**, the API adapter settles each call at its list price from usage, and Jev at its published rate (#216). So a settled hosted month should match the estimates above. This is inferred from the code, not measured on the hosted database.
- **While work runs, the allowance also holds reservations**: $1.08 per interpretation and $0.75 per revision (`ESTIMATE_USD` in `src/backend/providers/budget.ts`), and the tutor turn's own estimate, about $0.22 to $0.35 on Sonnet. An interpretation now costs $0.10 to $0.25 at list price, so a friend with less than $1.08 left cannot start one even though it would fit.

## The cut: short evidence labels

**Why.** The interpretation and revision prompts listed every passage and frame by its evidence ID, and the model cited them back. An ID such as `ev_gzzjdedljvdbaqdfktreozd2u3` is random base32. A `claude -p` call with 200 of them used 4,559 more input tokens than one with 200 labels such as `p12` (measured), so each ID costs about 25 tokens. In Fable's stored interpretations, IDs were 32% of the output characters.

**Change.** The prompt now names passages `p1`, `p2`, frames `f1`, `f2` in bundle order, and existing claims `c1`, `c2`. The task maps every cited label back to its ID before anything is stored, and a label it never showed is a retryable bad output, as an unknown ID was. Memo keys and task versions are unchanged, so stored lectures are not prepared again.

**Paired measurement.** For each of the 6 chunks of runs A and B, the stored interpretation input went through today's task and through the label task, once each, and every resulting claim went through Jev's claim check. The run's own call is a second sample of today's task.

| | Today, run's call | Today, replay | Labels |
| --- | --- | --- | --- |
| Output tokens, 6 chunks | 56,857 | 55,772 | 34,895 |
| Input tokens, 6 chunks | 141,923 | 139,575 | 118,222 |

| Wall time, 6 chunks | not compared | 707 s | 327 s |

| Claims Jev supported on first check | | 107 of 111 | 121 of 129 |

- The two samples of today's task differ by 2% in output. Labels wrote 37% to 39% less, and every one of the 6 chunks wrote less than both of its samples.
- The limiter is output tokens. Output is about 70% of an interpretation's cost, and labels cut it more than input because the model writes each cited ID in full.
- Accuracy was not audited. The proxies are Jev's first-check pass rate, 94% against 96%, and claim counts, which rose. A blind audit like experiment 4's would settle it.
- End to end, run C against run B: interpretation $0.76 to $0.51, revisions $0.53 to $0.44 with the same 5 revisions, preparation $1.34 to $1.00.

## Limits

- Three lecture runs and one review each. Revision counts vary from run to run, from 1 to 5 per 20 minutes here.
- The CLI's tokens stand in for the API's. The overhead correction is from a one-word call, and CLI calls that read images spend extra turns, so input may still be a little high.
- No hosted measurement. The hosted query that would confirm these figures is `select purpose, count(*), sum(cost_usd), sum(input_tokens), sum(output_tokens) from usage_events group by 1`.
